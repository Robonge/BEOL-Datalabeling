00 — Introduction

우리가 말하는 AI는 무엇인가

질문을 던지면 답을 돌려주는 채팅형 AI가 곧 "AI"라는 인식이 여전히 지배적입니다. 반도체 개발에 필요한 것은 정보를 바탕으로 상황을 파악하고, 판단하고, 실행까지 이어가는 AI 에이전트입니다. 그 모델은 ChatGPT · Gemini가 아니라 미국 국방부 등에서 쓰는 팔란티어(Palantir) 모델입니다 — 쏟아지는 정보와 복잡하게 얽힌 인과관계 위에서 판단을 돕는 것, 이것이 개인이 쓰는 AI와 Enterprise AI의 가장 큰 차이이자 어려움입니다.

02 — The Bottleneck

ChatGPT와 Claude에 업무를 물어보면
왜 만족스럽지 않을까

범용 LLM은 방대한 인터넷 일반 지식만 학습했습니다. 보안으로 격리된 사내 도메인 데이터는 모델 파라미터 안에 아예 존재하지 않습니다.

01
LIMIT 01

학습되지 않은 파라미터

BEOL 개발 이력, 사내 전용 약어, 세부 공정 내용을 물으면 엉뚱한 대답(할루시네이션)이 돌아옵니다. 해당 지식이 신경망에 없기 때문입니다.

사내 도메인 데이터는 학습된 적이 없다
02
LIMIT 02

설명 불가능성 (Black Box)

"왜 HOL 열화 혐의 step이 MND etch야?"라는 질문에 "학습한 가중치로는 이게 최적입니다"라는 답은 신뢰받지 못합니다.

결과의 타당한 근거를 논리적으로 제시하지 못한다
03
LIMIT 03

수치 · 시계열 데이터 처리 불가

LLM은 language model입니다. 글을 읽고 요약하는 데 특화되어, 쏟아지는 CD · ET data와 설비 FDC 데이터를 직접 분석하지 못합니다.

Fab 수치 데이터 앞에서는 무력하다

문서 검색의 한계 — 키워드 · 유사도 매칭

"M1 Short"이라는 단어가 들어간 과거 이력의 파편만 가져와 억지로 이어 붙입니다. 당시 왜 불량이 났는지에 대한 선행 공정의 인과관계, 장비 상태 변화, 검측 지표와의 연관성은 짚어내지 못합니다.

RETRIEVED · 실제로 돌아오는 답의 재료 "2024년 3월에 SF1.4에서 CMP time이 틀어지면서 M1 Short이 났습니다" "2025년 10월에는 SF1.0 BMV0에서 WDC hardmask가 무너지면서 M1 Short이 났습니다"

M1 Short의 원인은 여러 가지입니다

Spacer / I1 Etch 과다→WDC 붕괴→Short
Trench Etch 강함→ACI CD 증가→Short
unCMP→Short

LLM은 이 맥락을 이해하지 못한 채 단어가 겹치는 문서만 돌려줍니다.

    AI-Ready 데이터셋과 파이프라인

    온톨로지 구축의 성패는 IT 기술보다 현업의 전문성에 달려 있습니다. 네 단계의 워크플로우로 지식이 한 번 만들어지고 끝나지 않고 계속 살아 움직이게 합니다.

    현장의 맥락을 가장 잘 아는 사람이 지식의 뼈대를 세웁니다

    팔란티어(Palantir)가 현장 파견 엔지니어(FDE)를 국방부나 병원에 보내듯, 우리 조직에서는 BEOL 인테그레이션 엔지니어 본인이 온톨로지스트가 되어 데이터 간의 올바른 의미 관계(스키마)를 직접 설계합니다.

    타 산업 벤치마킹 · 의료 분야 SNOMED CT — 독립된 관찰값을 입력하면 온톨로지가 이를 엮어 추론합니다. 아래 관찰값을 눌러 보세요.

    과거 문서에서 숨은 인과관계를 자동으로 끌어냅니다

    방대한 기술 문서와 리포트에서 AI 모델이 두 개체 사이의 의미와 인과 관계를 추출해 초기 지식 그래프(Knowledge Graph)를 생성합니다. 추출 결과는 아래 HITL 검증을 거쳐 그래프에 반영됩니다.

    한 번 구축하고 끝나지 않는, 살아 있는 지식

    • 지속적 유입 — 매일 생성되는 모듈 회의록 · 수율 분석 리포트와, 설비에서 쏟아지는 Fab 시계열 · 수치 데이터를 파이프라인에 계속 공급합니다.
    • AI-Readable 정제 — 데이터 레이크의 Raw Fab 데이터를 Text-to-SQL과 정제 파이프라인으로 AI가 즉시 읽을 수 있는 형태(AI-Readable CSV 등)로 바꿉니다.
    • Triplification — 정제된 데이터는 온톨로지 스키마 규칙에 따라 쪼개지고 관계가 부여되어 그래프 DB에 실시간으로 적재됩니다.

    표준에서 시작해 공정별로 끊임없이 최적화합니다

    반도체 제조 표준 공정 온톨로지를 먼저 구축하고, 지속 업데이트되는 파이프라인을 바탕으로 사내 환경에 맞춰 세부 공정별(Cu, Ru 메탈 등)로 계속 다듬습니다. 한 번 만든 스키마는 다른 모듈에서도 재사용됩니다.
