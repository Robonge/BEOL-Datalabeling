02 — WHY

label을 붙이면 원하는 자료를 정확히 찾고,
AI에게 넘기면 원하는 답이 나옵니다

지금 — EDM, label이름표 없는 창고

EDM 검색TiN spacer

"비슷한 평가, 예전에 했던 것 같은데…"

못 찾으면 → 담당자 수소문 "혹시 이 평가 아시는 분?" "그때 담당자가 했을 텐데…" "그분은 팀을 옮기셨어요"

keyword로는 파일을 하나씩 열어 봐야 하고, 결국 쓴 사람을 수소문합니다. 맥락이 글에 없고 쓴 사람 머릿속에만 있기 때문입니다.

EDM keyword 검색, 담당자 수소문의 한계

바꾸고 싶은 모습 — 우리 자료를 읽은 AI가 찾아 주는 맞춤형 답변

    07 — TRUST

    AI가 틀리면 어떡하죠?
    그래서 세 겹으로 확인합니다

    1겹 · 검증 질문

    LLM이 자기 label을 O/X로 다시 확인한다

    label마다 "정말 맞아?"를 묻고 원문 근거를 붙입니다. 근거가 없거나 확신이 낮으면 불량 chunk의심 조각로 넘깁니다.

    2겹 · 감시 agent

    라벨링 agent와 감시 agent를 나눴다

    Domain-Engr-bot은 엔지니어에게 물어 label 규칙을 보강하고, Code-Engr-bot은 코드 규칙과 분류표 변경을 점검합니다.

    3겹 · human in the loop

    마지막 결정은 엔지니어가 한다

    사람이 고친 값이 최종 label입니다. "검수 완료" 전에는 DB에 올리지 않습니다.

    사내 문서는 밖으로 나가지 않습니다. 사외 개발은 더미연습용 가짜 자료로만 하고, 사내 파일은 DRM문서 보안 규칙에 따라 한 곳에서만 엽니다.
