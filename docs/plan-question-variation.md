# 계획: 대조 질문 60%와 질문 다양화

작성 2026-10-05. 대상 `labelbot` 2차(질문 생성). 기존 설계는 `plan.md` M3 "대조 질문 규칙"을 따른다.

## 결정 사항 (사용자, 2026-10-05)

| 항목 | 결정 |
|---|---|
| 대조 질문 비율 | `limits.control_ratio` 기본값 0.3 → **0.6** |
| 질문 상한 | `limits.questions_per_chunk` **8 유지** |
| 다양화 방법 | `gpt-6-sol`은 temperature를 받지 않는다(이미 미전송 = 모델 기본값). **프롬프트에 문형·관점을 지정**해 다양화한다 |
| 다양성 범위 | **한 실행 안에서 chunk 간 다양성**. 같은 입력을 다시 돌리면 같은 질문이 나온다(캐시·`label_hash` 유지) |

## 1. 대조 비율 0.6

### 바뀌는 숫자
- 승인 질문 1개(Q-COM-001)를 빼면 남은 칸은 7개다.
- `split_budget`로 나누면 다음과 같다.
  - 1차 라벨 5개 이상: 검증 3, 대조 4(57%). 지금(0.3)은 검증 5, 대조 2다.
  - 라벨 2개: 검증 2, 대조 3.
  - 라벨 1개: 검증 1, 대조 2.
- 직전 실행(20261005T075633-685f)은 chunk당 검증 질문이 평균 4.8개였다. 0.6이면 chunk당 1~2개 라벨이 검증 대상에서 빠진다.

### 검증할 라벨 고르기 (새 규칙)
- 지금은 taxonomy 축 순서대로 자른다. 그래서 뒤쪽 축은 늘 검증에서 빠진다.
- 바꾸는 규칙:
  - 1차 분류의 축 확신도가 낮은 순으로 고른다. 같으면 축 순서를 따른다.
  - 칸이 줄어도 틀렸을 가능성이 큰 라벨이 먼저 검증된다.
  - 고르는 순서만 바꾸고, 프롬프트 안의 질문 순서는 지금처럼 질문 ID 순(맹검)이다.

### 손볼 곳
- `labelbot/workspace.py`: `DEFAULT_CONFIG.limits.control_ratio` 값을 0.6으로 바꾼다.
  - 작업 폴더 `pipeline.json`에 `limits`가 없으면 이 기본값이 그대로 들어간다. `init_workspace.py`가 만드는 설정에는 `limits`가 없다.
- `labelbot/questions.py`: `verify_targets`에 확신도 정렬 선택지를 둔다. 승인 질문 매핑(`map_questions`)과 화면은 지금 순서를 쓰므로 그쪽 동작은 그대로 둔다.
- `tests/contracts/snapshots/constants.json`: 기본 설정이 바뀌므로 갱신한다(`CONTRACT_UPDATE=1`).

## 2. 문형·관점으로 다양화

### 원칙
- 검증 질문(Q-GEN)은 "이 라벨이 맞는가"라는 범위를 바꾸면 안 된다.
  - 관점을 좁히면 맞는 라벨인데도 X·N/A가 나와 검증 신호가 망가진다.
  - 예: "M1 배선층의 측정 결과를 다루는가?"는 M1 공정 조건 슬라이드에서 틀린 X를 낸다.
  - 그래서 검증 질문은 **문형만** 바꾼다.
- 대조 질문(Q-CTL)은 **문형과 근접 오답 관점**을 함께 준다.
  - 본문에 나온 대상·조건·수치 같은 요소를 빌려, 붙지 않은 라벨과 엮어 묻는다.
  - 예: "이 슬라이드의 CD 측정은 M4 배선층을 대상으로 하는가?"
  - 제목만 보고도 X라고 할 수 있는 쉬운 대조군 대신, 본문을 읽어야 답할 수 있는 대조군이 된다. 원래 요청한 "O/X 퀴즈의 의미"에 가장 가까운 형태다.
- 문형·관점은 sha256(chunk_id|축|값|용도)로 정한다. 그래서 chunk마다 달라지고, 재실행하면 같다.

### 문형 목록 (예, 범위가 같은 판정 의문문)
1. "이 chunk는 ~을 다루는가?"
2. "본문에 ~에 해당하는 내용이 있는가?"
3. "이 슬라이드의 내용은 ~에 관한 것인가?"
4. "본문에서 ~이 언급되는가?"
5. "이 자료가 설명하는 대상은 ~인가?"

### 대조 질문 관점 목록 (예)
- 본문의 공정 조건·레시피와 엮기
- 본문의 측정 항목·수치와 엮기
- 본문의 불량·이상 현상과 엮기
- 본문의 평가 판정·결론과 엮기
- 본문의 구조·층·위치와 엮기

### 손볼 곳
- `labelbot/questions.py`:
  - 문형·관점 목록과 고르는 함수를 둔다.
  - `_target_lines`가 대상 줄 끝에 `[문형 n]`, `[관점: …]`을 붙인다.
- `prompts/question_gen.md`: 규칙을 더한다.
  - 문형 번호를 따라 쓴다.
  - 검증 질문은 범위를 좁히지 않는다.
  - 대조 질문은 관점의 본문 요소를 빌리되, 본문을 그대로 인용하지 않는다.
  - 한 문장에 한 가지만 묻는다.
  - 기존 금지 규칙(개방형·복합·부정 의문문)은 그대로 둔다.
- 프롬프트가 바뀌므로 첫 실행에서 질문 생성 캐시가 한 번 무효가 된다. 의도한 동작이다.

## 4. 위험과 대응

| 위험 | 대응 |
|---|---|
| 검증 질문이 chunk당 3개로 줄어 1차 라벨 일부를 검증하지 못한다 | 확신도 낮은 라벨부터 검증한다. `[question]` 줄의 "검증하지 못한 라벨" 수를 실제 실행 비교에 넣는다 |

| 문형 지정이 검증 질문의 범위를 바꾼다 | 문형 목록은 범위가 같은 판정 의문문만 두고, 프롬프트에 "범위를 좁히지 않는다"를 명시한다 |
| golden 스냅샷 | 이번 변경으로 또 바뀐다. 다른 세션의 `taxonomy.xlsx` 변경이 확정된 뒤 한 번에 다시 만든다 |

## 5. 추가 변경: 검증 질문 대상 축소 (사용자, 2026-10-05)

1절의 "검증할 라벨 고르기"를 아래 규칙이 대신한다.

### 대상
- 검증 질문은 1차 라벨마다 묻지 않는다. 아래 두 가지에만 묻는다.
  - 1차가 unknown이라 한 활성 축
  - 축 확신도가 `flag.confidence_min`(0.7) 미만인 붙은 라벨
- 확신도 낮은 순(unknown은 0으로 본다)으로 최대 `limits.verify_max`(3)개를 고른다.
- 대상이 하나도 없으면 검증 질문 없이 대조 질문만 낸다.
- 비율 0.6에서 검증 대상 3·2·1·0개일 때 대조 질문은 4·3·2·2개다.

### unknown 축 질문
- unknown 축에는 붙은 값이 없다. 그래서 질문 생성 LLM이 그 축의 taxonomy 후보 값 중 본문에 가장 가까운 값 하나를 골라 출제한다.
- 검증기는 후보 밖 값, 한 축에 두 개 이상 낸 질문, 빠진 축을 거부한다.
- 그 질문에 O가 나오고 인용이 본문에 있으면 불량 사유 `UNKNOWN_O`로 검수에 오른다. unknown을 그 값으로 채울 후보라는 뜻이다.

### mock 확인
- 더미 769 chunk에서 검증 질문이 2,066개에서 611개로 줄었다.
- 대조 질문은 1,774개다.
