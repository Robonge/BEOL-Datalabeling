S4

팀 소개 — 지휘자와 네 명의 agent

요청 3 · multi agent약 2분
04 — TEAM

이 일은 AI 한 명이 아니라 팀이 합니다

연출 캐릭터를 누르면 그 agent의 선만 점등되고 데이터 알약이 선을 따라 흐른다. 옆에 "받는 것 / 하는 일 / 내놓는 것" 카드가 열린다. 지휘자를 누르면 네 agent가 호출 순서대로 차례로 켜진다. 사실 관계 agent끼리 직접 대화하지 않고 공유 작업대(작업 폴더)를 거쳐 주고받는다. 코드 감사관은 자료가 아니라 프로그램 코드를 본다. 점선 뱃지는 아직 구현 전이다(도메인 AI 심사 L4B, 검수 화면 연결, 실행 흔적·AI 코드 리뷰 C5·C6).

S6

믿을 수 있는 이유 — 세 겹 확인

약 1분
06 — TRUST

AI가 틀리면 어떡하죠?
그래서 세 겹으로 확인합니다

1겹 · 스스로 되묻기

AI가 자기 답에 O/X 질문을 던진다

이름표마다 "정말 맞아?"를 확인하고, 근거 문장을 원문에서 그대로 인용합니다. 인용문이 원문에 없으면 의심 목록에 올립니다.

2겹 · 다른 AI의 검사

검수관과 감사관이 따로 본다

이름표를 붙인 AI와 검사하는 AI를 분리했습니다. 검수관은 이름표를, 감사관은 프로그램 코드를 봅니다.

3겹 · 사람의 확정

마지막 결정은 엔지니어가 한다

사람이 고친 값이 최종 이름표입니다. "검수 완료"를 누르기 전에는 지식 DB에 올리지 않습니다.

회사 문서는 밖으로 나가지 않습니다. 회사 밖 개발은 연습용(더미) 자료로만 합니다.

연출 카드 3장이 겹겹이 쌓이듯 차례로 나타난다. 요청 항목에는 없던 장면이라 빼도 된다(일반 청중의 "AI를 믿어도 되나"에 답하려고 넣었다).
